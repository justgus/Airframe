## I-0026: AgileCockpit cannot view or modify non-current Review Sprint

**Status:** Implemented - Verified
**GitHub Issue:** #176
**Severity:** High
**Epic:** EP-024
**Sprint Assigned:** SP-037
**Date Reported:** 2026-07-06
**Date Resolved:** 2026-07-06
**Date Verified:** 2026-07-06

**Observed Behavior:**
AgileCockpit exposes the current Active Sprint as the primary Sprint surface. When SP-036 is in Review and SP-037 is Active, there is no visible UI path to select SP-036, inspect it, or perform the policy-allowed Review -> Backlog transition.

**Expected Behavior:**
A human reviewer should be able to find Review Sprints that are not the current Active Sprint, inspect their state, and perform allowed human-authorized transitions such as Review -> Backlog.

**Reproduction Steps:**
1. Open AgileCockpit with SP-037 as the active Sprint and SP-036 in Review.
2. Navigate to the Sprint controls or current Sprint surface.
3. Observe that the UI focuses on SP-037.
4. Attempt to find SP-036 as a non-current Review Sprint.
5. Observe that there is no UI path to view SP-036 or move it back to Backlog.

**Affected Components:**
- AgileCockpit
- Sprint Workflow
- Canonical State

**Notes:**
- Observed after SP-036 was moved to Review during reprioritization to EP-024/SP-037.
- The current active Sprint is SP-037, so current-Sprint UI affordances do not expose SP-036.
- This is distinct from I-0025. I-0025 covers workflow authority and policy for returning Active or Review Sprints to Backlog. This issue covers AgileCockpit access to non-current Review Sprints and their allowed actions.
- Resolution: AgileCockpit Sprint Work now lists Review Sprints separately from the current Active Sprint, lets the human select a Review Sprint, shows its Epic, Tasks, Issues, and status, and provides a Return to Backlog action that applies the canonical Review -> Backlog transition, records audit, refreshes state, and regenerates projections.
