## I-0029: Allow implemented-not-verified and active issue rollback transitions

**Status:** Backlog
**GitHub Issue:** TBD
**Severity:** High
**Epic:** EP-024
**Sprint Assigned:** TBD
**Date Reported:** 2026-07-07
**Date Resolved:** TBD
**Date Verified:** TBD

**Observed Behavior:**
The current issue workflow rejects Implemented - Not Verified -> Active transitions, which blocks the requested rollback path. Active -> Backlog remains the only currently allowed rollback path visible in the policy model.

**Expected Behavior:**
Implemented - Not Verified issue work items should be allowed to return to Backlog or Active, and Active issue work items should be allowed to return to Backlog, subject to the usual authority and workflow checks.

**Reproduction Steps:**
1. Attempt to move an Issue from Implemented - Not Verified to Active using AICockpit.
2. Observe that the transition is rejected by workflow validation.
3. Attempt to move an Issue from Active to Backlog using the current workflow.
4. Observe the current policy behavior and compare it with the requested rollback requirement.

**Affected Components:**
- AirframeCore
- AICockpit
- Canonical State

- TBD

**Notes:**
- This issue records a workflow requirement that was not previously captured in the policy model.
- Required rollback transitions: Implemented - Not Verified -> Backlog, Implemented - Not Verified -> Active, and Active -> Backlog.
- The implementation should preserve normal authority evaluation and should not weaken human-only closeout controls.
- Acceptance Criteria: Canonical workflow policy allows the required rollback transitions for Issues.
- Acceptance Criteria: AICockpit status commands expose the allowed rollback transitions and reject disallowed ones with a clear reason.
- Acceptance Criteria: Workflow and command tests cover the rollback paths and preserve the existing human-only gates.
