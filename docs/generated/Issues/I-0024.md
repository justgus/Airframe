## I-0024: Requirements traceability matrix includes excessive derived work links

**Status:** Implemented - Verified
**GitHub Issue:** #168
**Severity:** High
**Epic:** EP-023
**Sprint Assigned:** SP-036
**Date Reported:** 2026-07-06
**Date Resolved:** 2026-07-06
**Date Verified:** 2026-07-06

**Observed Behavior:**
The Requirements Traceability Matrix includes broad Epic, Sprint, Task, and Issue lists for requirements, producing a very large and noisy table.

**Expected Behavior:**
The Requirements Traceability Matrix should contain only the durable trace needed for requirements review: Requirement to acceptance criteria, including the Epic/AC identifier for each verifying acceptance criterion. Sprint, Task, and Issue expansion should not be included in the matrix.

**Reproduction Steps:**
1. Open the generated Requirements Traceability Matrix.
2. Inspect requirement rows.
3. Observe broad lists of Epics, Sprints, Tasks, and Issues rather than a focused Requirement-to-Epic/AC mapping.

**Affected Components:**
- AgileCockpit
- AirframeCore
- Requirements Traceability

**Evidence:**
- TBD

**Notes:**
- Acceptance criteria should be uniquely identifiable in the matrix. If AC IDs are not globally unique by themselves, the displayed trace should include the Epic and AC, such as EP-XXX-AC-YY.
- The Requirement-to-Epic/AC mapping should only change when a Requirement or acceptance criterion changes, so it should be stored or projected from stable canonical links instead of derived during tab rendering.
- Resolution: Requirements Traceability Matrix projection now contains only Requirement, Title, Status, and Epic Acceptance Criteria. Acceptance criterion display includes the owning Epic when needed for uniqueness, and the matrix no longer emits Sprint, Task, Issue, Evidence, Revision, or target-kind columns.
