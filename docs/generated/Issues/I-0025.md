## I-0025: Active Sprint cannot be returned directly to Backlog

**Status:** Implemented - Verified
**GitHub Issue:** #175
**Severity:** High
**Epic:** EP-024
**Sprint Assigned:** SP-037
**Date Reported:** 2026-07-06
**Date Resolved:** 2026-07-06
**Date Verified:** 2026-07-06

**Observed Behavior:**
During reprioritization from SP-036/EP-023 to SP-037/EP-024, AICockpit rejected moving SP-036 from Active to Backlog with an invalid workflow transition error. SP-036 had to be moved to Review instead even though the intended planning outcome was to return it to the Backlog.

**Expected Behavior:**
A human-authorized workflow should allow a Sprint in Active or Review state to return to Backlog when planning priorities change. The operation must preserve auditability, update or clear active Sprint pointers when needed, and keep task and issue relationships consistent unless a separate reassignment action is explicitly performed.

**Reproduction Steps:**
1. Start with a Sprint in Active status.
2. Run or invoke the Sprint status change to Backlog.
3. Observe that the workflow rejects Active -> Backlog as an invalid transition.
4. Move the Sprint to Review and observe that Review -> Backlog is policy-defined separately.

**Affected Components:**
- AirframeCore
- AICockpit
- AgileCockpit
- Sprint Workflow

**Notes:**
- Review -> Backlog is already present in the workflow policy. Active -> Backlog is currently rejected as an invalid transition.
- Recommended authority: human project owner or maintainer only. Agents may propose or report the need, but should not perform reprioritization without explicit human authorization.
- Recommended implementation: expose a controlled Sprint return-to-backlog operation that records human actor, rationale, previous state, target state, and active-pointer effects. If implemented as a direct Active -> Backlog transition, it should be explicitly policy-gated and audited. If implemented as a compound operation, it should not require manual Review as an artificial intermediate step.
- Verification of I-0023 and I-0024 was not the blocker. The failed operation occurred because Active -> Backlog was not an allowed Sprint workflow transition.
- Resolution: AirframeCore now allows Sprint Active -> Backlog as a canonical Sprint-control transition using OP-RETURN-SPRINT-TO-BACKLOG, keeps the operation human-owner/maintainer controlled, and clears the active Sprint pointer when the returned Sprint is current. AgileCockpit now exposes a Return Active Sprint to Backlog action for the configured Active Sprint.
