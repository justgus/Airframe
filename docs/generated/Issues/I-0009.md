## I-0009: Epic close leaves stale active pointers and sprint closeout state

**Status:** Implemented - Verified
**GitHub Issue:** #147
**Severity:** High
**Epic:** TBD
**Sprint Assigned:** TBD
**Date Reported:** 2026-06-25
**Date Resolved:** 2026-06-25
**Date Verified:** 2026-06-25

**Observed Behavior:**
Closing EP-021 in AgileCockpit transitioned the Epic to Closed but left active project pointers referencing closed EP-021 and SP-032. SP-033 also remained open in canonical Sprint state even though closeout direction expected it to be closed.

**Expected Behavior:**
When AgileCockpit closes an Epic, canonical project state should clear the active Epic pointer. Active Epic UI, release gate scope, and traceability scope should read the canonical project snapshot rather than stale configuration. Sprint closeout data should not leave a closed Sprint configured as active, and follow-up work should define whether closing a Sprint should advance, clear, or require explicit selection of the next current Sprint.

**Reproduction Steps:**
1. Close SP-032 and EP-021 through AgileCockpit.
2. Open Data Health diagnostics.
3. Observe activeEpicNotActive and activeSprintNotActive diagnostics for closed work.

**Affected Components:**
- AgileCockpit
- AirframeCore
- Canonical State

**Notes:**
- Description: Closing EP-021 in AgileCockpit transitioned the Epic to Closed but left the project active Epic pointer on EP-021. The project active Sprint pointer also remained stale on SP-032 after SP-032 and SP-033 were closed, which caused Data Health diagnostics to report closed work as active and exposed that active pointer cleanup was incomplete.
- Resolution: Added canonical active Epic clearing support, wired AgileCockpit Epic close to clear the canonical active Epic pointer, switched active Epic UI and scope reads to canonical project state, repaired EP-021 and SP-033 canonical and Markdown closeout state, and restored the missing SP-029 canonical Sprint record.
- Follow-up: Investigate and define current Sprint advancement behavior after closing a Sprint when another Sprint is already closed, active, or absent. Decide whether AgileCockpit should update `.airframe/airframe-workspace.json` active pointers or treat canonical project state as the only mutable active pointer source.
