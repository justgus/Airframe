## I-0023: Requirements tab freezes while loading traceability data

**Status:** Implemented - Verified
**GitHub Issue:** #167
**Severity:** High
**Epic:** EP-023
**Sprint Assigned:** SP-036
**Date Reported:** 2026-07-06
**Date Resolved:** 2026-07-06
**Date Verified:** 2026-07-06

**Observed Behavior:**
Clicking the Requirements tab in AgileCockpit freezes the app with the macOS spinning beachball and does not display content in a reasonable period of time. The user has to force quit AgileCockpit to continue.

**Expected Behavior:**
The Requirements tab should remain responsive and display requirements content within a reasonable time. Expensive traceability analysis must not block the main UI thread.

**Reproduction Steps:**
1. Launch AgileCockpit.
2. Click the Requirements tab.
3. Observe that the app freezes before displaying usable content.

**Affected Components:**
- AgileCockpit
- Requirements

- TBD

**Notes:**
- May be related to current Requirements Traceability Matrix generation deriving broad Epic, Sprint, Task, and Issue relationships on demand.
- Resolution: AgileCockpit now computes Requirements tab traceability rows once during model load/refresh and stores them as published state instead of rebuilding the traceability index repeatedly during SwiftUI rendering. The Requirements tab traceability rows use only requirement-to-acceptance-criterion data and no longer derive broad Epic, Sprint, Task, or Issue link text for the matrix.
- Evidence: swift test --package-path AirframeCore passed on 2026-07-06. swift test --package-path AICockpit passed on 2026-07-06. xcodebuild test -project AgileCockpit/AgileCockpit.xcodeproj -scheme AgileCockpit -destination 'platform=macOS' -only-testing:AgileCockpitTests passed on 2026-07-06. Full xcodebuild test built and ran AgileCockpitTests, but AgileCockpitUITests-Runner failed to initialize automation mode.
