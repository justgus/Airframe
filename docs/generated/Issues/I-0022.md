## I-0022: Display and analysis paths may still read file-based state instead of canonical state

**Status:** Implemented - Verified
**GitHub Issue:** #160
**Severity:** High
**Epic:** EP-022
**Sprint Assigned:** TBD
**Date Reported:** TBD
**Date Resolved:** TBD
**Date Verified:** 2026-06-30

**Observed Behavior:**
Recent AgileCockpit behavior showed dashboard-style views and detail or criteria views disagreeing about the current Epic because some display and analysis paths still read stale file or configuration-derived state instead of canonical state. The EP-022 active-Epic mismatch suggests this may be a broader migration gap after moving from file-based documentation analysis to canonical state.

**Expected Behavior:**
Every app display, dashboard, detail, planning, data-health, release-gate, and analysis path that reasons about Airframe work state should read from canonical state or an explicitly documented canonical projection. File-system Markdown should be treated as import/export/projection material, not as authoritative runtime state.

**Reproduction Steps:**
1. Create or observe canonical state where the canonical project and canonical work records disagree with stale file or configuration-derived state.
2. Open AgileCockpit dashboard, planning tabs, criteria tabs, data-health, and status/detail views.
3. Compare displayed current Epic/Sprint/work relationships and analysis diagnostics.
4. Observe any path that still reports file/config-derived state instead of canonical state.
