## I-0018: Canonical backend lacks a create path for missing records

**Status:** Implemented - Verified
**GitHub Issue:** #155
**Severity:** High
**Epic:** EP-022
**Sprint Assigned:** SP-034
**Date Reported:** TBD
**Date Resolved:** 2026-06-26
**Date Verified:** 2026-06-26

**Observed Behavior:**
The canonical backend can repair and mutate existing records, but it cannot create missing canonical records through the CLI.

**Expected Behavior:**
The canonical backend should support controlled creation of missing canonical records where the workflow requires it.

**Reproduction Steps:**
1. Attempt to materialize a missing canonical record through the CLI.
2. Observe that the canonical backend rejects the create path.
3. Note that reconciliation paths requiring record creation are blocked.

**Affected Components:**
- AICockpit
- AirframeCore
- Canonical Store

- TBD

**Notes:**
- Acceptance Criteria: 1. Canonical backend exposes a create path for permitted record kinds. 2. Missing canonical records needed by repairs can be created without manual JSON edits. 3. Regression coverage proves the canonical create path works for the intended record types.
- Resolution: Verified AICockpit canonical create commands route through the canonical backend and link created records to their owning Epic and Sprint.
